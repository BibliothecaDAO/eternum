# Delegated asset work

Use when splitting asset preparation, technical work or review. Preserve the selected parent model and use the personal
`eternal-workflow/references/models-and-goals.md` for model tuning; if that optional skill is unavailable, retain the
user's settings and this asset contract.

The coordinator owns the accepted visual brief, unresolved tradeoffs and final integration. Delegate bounded inspection,
Blender scripting, rig/export tooling or an approved local repair with the exact source and allowed delta. Inventorying
hashes, missing views or review receipts is separable work; it cannot certify visual fidelity. Give visual reviewers the
approved concept, raw mesh, current source/export and matched views, not only a prior agent's verdict.

One owner controls live Blender MCP across all tasks; likewise coordinate shared browser/preview ownership. Other
workers may inspect saved renders or prepare independent code while the owner operates the scene. Record the owning
task, source/save path, handle and handoff condition in the existing asset checkpoint. Validate ownership before taking
over a seemingly stale session; never overwrite another asset's scene. Separate worktrees alone do not isolate these
tools.

Keep concept approval, raw-mesh approval, ideal-source acceptance, derivative-preset fidelity, runtime evidence and
publication distinct. Pass hashes and actual approval status in the handoff. A valid GLB, screenshot capture or unit
test is not proof of human visual review, native gameplay or production eligibility. Directed repairs retain existing
authorization; new design decisions, provider spend or unapproved stages retain their real gates. Cheap worker tokens do
not authorize extra Tripo generations.
