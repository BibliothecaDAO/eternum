# Crossbowman pathway

Use a Crossbowman-owned asset brief and namespace. Begin from the latest lean infantry concept, not the archived Knight
or Paladin rig dimensions. Skin includes anatomy, clothing, leather/armor, cap and boots. The primary crossbow and
secondary lower-back bolt quiver are separately removable family items. Neither offhand placement nor a bow is an
adequate substitute for this two-hand weapon contract.

Record the primary grip and supporting-hand grip on the weapon, outward bolt/muzzle direction, string/limb landmarks and
quiver opening/bolt direction. These are weapon landmarks, not mandatory extra human bones. Keep the weapon its authored
size and solve the support hand to it. Inspect arrowhead forward, feathers rear, plausible taut string geometry,
wrist/stock clearance and the quiver against torso/legs. Follow intentional omissions in the approved concept (including
a stringless reference); diagnostic string/bolt axes can be landmarks without adding unapproved geometry. Allow
sufficient anatomy beneath bending clothing seams.

Validate actual bind/neutral, two-hand carry and affected arm/torso/leg ROM. Check every 1–6 formation using the
crossbow width and quiver envelope. Preserve both grip/contact frames in lower representations; fixed palettes need no
infantry texture-identity pool.

Own a Crossbowman controller/profile behind the existing runtime. Track idle, walk, run, attack and defend separately.
Locomotion should preserve a believable supported carry. Attack requires a real aim/release/recovery pathway; optional
reload must use agreed gameplay/cosmetic timing. Current crossbow carry does not prove firing works. Defend is a
family-appropriate protective stance, not an invented shield or damage mechanic. Read active code before declaring
capabilities; record unsupported states. Use [motion references](../procedural-animation.md) for action development.
