# Get the data

Every confirmed fact in Frontier is public onchain. You can read game state, Aspect standings, and story history
straight from Herald over HTTP, or query the shard RPC without an API key or account.

- Herald base URL is **{PUBLIC_DATA.heraldUrl}** (GET requests, `Access-Control-Allow-Origin: *`).
- Shard Starknet JSON-RPC URL is **{PUBLIC_DATA.rpcUrl}** (POST requests, `Access-Control-Allow-Origin: *`).

Both endpoints work from `curl`, Node.js, Python, and browser pages. If you use Python's `urllib`, send a standard
`User-Agent` header so edge filters accept your request.

## Public routes

All examples below were run against production on 24 November 2026 during Final Testnet registration (`game_id: 1`,
`testnet-1795521600`), with long responses shortened. Once Season 1 opens, pick the game whose `name` starts with
`frontier-` from `/games`.

### 1. Game directory (`GET /games`)

Lists every game on the shard with its clock, player count, Aspect member counts, and hyperstructure heights. Pass an
optional `?player=0x...` address to include that player's state.

<CopyCode>{PUBLIC_DATA.snippets.gamesCurl}</CopyCode>

<CopyCode>{PUBLIC_DATA.snippets.gamesJs}</CopyCode>

Shortened response from production:

```json
{
  "confirmed_block": 49678,
  "world_address": "0xaadbe833ac33670c8c2aa05ce406a07f44742582def994ae1e601ae84f4a3",
  "games": [
    {
      "game_id": 1,
      "name": "testnet-1795521600",
      "mode": "frontier",
      "status": "Registration",
      "player_count": 0,
      "settled_realms_count": 0,
      "aspect_members": { "1": 0, "2": 0, "3": 0, "4": 0 },
      "aspect_race": {
        "finish_height": 10000,
        "season_days": 50,
        "heights": { "1": 0, "2": 0, "3": 0, "4": 0 }
      },
      "clock": {
        "start_settling_at": 1795521600,
        "start_main_at": 1795521600,
        "end_at": 1796169600,
        "scheduled_end_at": 1796169600
      }
    }
  ]
}
```

| Field                                   | Meaning                                                                             |
| --------------------------------------- | ----------------------------------------------------------------------------------- |
| `confirmed_block`                       | Latest confirmed Madara block folded by Herald.                                     |
| `game_id`                               | Numeric ID used in `/games/<game_id>/...` routes.                                   |
| `name`                                  | Game slug (`testnet-<timestamp>` for testnet, `frontier-<timestamp>` for Season 1). |
| `status`                                | Game lifecycle state (`Registration`, `Live`, `Ended`).                             |
| `player_count` / `settled_realms_count` | Enrolled players and created realms in the game.                                    |
| `aspect_members`                        | Member count per Aspect ID.                                                         |
| `aspect_race`                           | `finish_height`, `season_days`, and current `heights` per Aspect ID.                |
| `clock`                                 | Unix timestamps in seconds for settling start, main start, and end.                 |

### 4. Current state snapshot (`GET /games/<id>/snapshot?models=...`)

Returns current confirmed rows for the models you name in `models` (comma-separated). Always pass `?models=...` so you
only download the tables you need. You can also pass `&actor=0x...` or `&owner=0x...` to narrow rows to one player.

Useful Season 1 model names are `AspectHyperstructure`, `AspectMembers`, `AspectActivity`, `HomeAspect`, `RaceMember`,
`RaceResult`, `ExplorerTroops`, `DeepArmy`, `DeepSite`, `DeepGuard`, `AltarBar`, `WorldBane`, `TeamBane`, `Seal`, and
`Structure`. Numeric values inside snapshot rows are hex strings (`"0x..."`), which `BigInt(value)` parses cleanly.

<CopyCode>{PUBLIC_DATA.snippets.snapshotJs}</CopyCode>

### 5. Aspect Glory roster (`GET /games/<id>/aspects/<aspect_id>/members`)

Season 1 ranks players by Glory inside each Aspect. Calling `/games/<id>/leaderboard` on a Season 1 game returns
`404 {"error":"season_one_ranks_aspects"}`, so read `/aspects/<aspect_id>/members` instead.

Page size `limit` defaults to {PUBLIC_DATA.limits.rosterDefault} and accepts 1 to {PUBLIC_DATA.limits.rosterMax}. Use
`offset` to walk the full roster. The response also includes an `X-Confirmed-Block` header.

<CopyCode>{PUBLIC_DATA.snippets.membersCurl}</CopyCode>

<CopyCode>{PUBLIC_DATA.snippets.membersJs}</CopyCode>

Response from production:

```json
{
  "game_id": "1",
  "aspect": 1,
  "total": 0,
  "limit": 50,
  "offset": 0,
  "members": []
}
```

Each entry in `members` has `rank` (1-based integer), `entity_id` (realm entity ID string), `realm_id` (integer),
`owner` (Starknet address hex string), and `glory` (decimal string).

### 6. Story history (`GET /games/<id>/history`)

Returns confirmed immutable events ordered newest first, with `complete_through_block` and `total`. Filter by
`model=StoryEvent` and optional `story` variant (`RealmCreatedStory`, `ExplorationReward`, `BattleEvent`, `SitePayout`,
`ExplorerCreateStory`, `StructureLevelUpStory`), `owner=0x...`, or `entity_id=<decimal>`.

Page size `limit` defaults to {PUBLIC_DATA.limits.historyDefault} and accepts 0 to {PUBLIC_DATA.limits.historyMax}.

<CopyCode>{PUBLIC_DATA.snippets.historyCurl}</CopyCode>

<CopyCode>{PUBLIC_DATA.snippets.historyJs}</CopyCode>

Response from production:

```json
{
  "complete_through_block": 49679,
  "items": [],
  "limit": 100,
  "offset": 0,
  "total": 0
}
```

Each item in `items` has `block_number`, `transaction_index`, `event_index`, `transaction_hash`, `game_id`, `model`, and
`value` (where `value.timestamp` holds the Unix timestamp in seconds as a hex or decimal string).

Herald also exposes `GET /games/updates` (a Server-Sent Events stream that emits `data: changed` when the game directory
changes), `GET /games/<id>/days/<day>/ranks` (closed Frontier day ranks, `404` until a day closes), and
`GET /games/<id>/review/snapshot` (frozen snapshot after a game ends, `404` while live).

## Rate etiquette

Herald serves public reads with `Cache-Control: no-store`, so every request reaches the server. Keep your script polite:

- Cache responses on your side for at least 60 seconds (or 1 hour for dashboards and spreadsheets).
- Always pass `?models=` on `/snapshot` instead of requesting the whole world.
- Use the maximum page size (`limit=`{PUBLIC_DATA.limits.rosterMax} on `/members`, `limit=`
  {PUBLIC_DATA.limits.historyMax} on `/history`) and page sequentially rather than firing dozens of concurrent offsets.
- Subscribe to `GET /games/updates` (SSE) instead of polling `/games` every second.
- Do not scan tens of thousands of historical blocks over RPC from a browser; read Herald's folded `/snapshot` and
  `/history` routes instead.
