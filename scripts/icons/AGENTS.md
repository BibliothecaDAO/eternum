# Icon delivery rules

| Rule                                                                                                                                   | Enforcement                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| -------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| The visible subject fills at least 85% of the square's longest side; target 90%. Use subject-only model renders without terrain tiles. | `normalizeMaster` crops at alpha 128, fits 920/1024, and asserts fill. `deliverIcon` crops for the final pixel size and checks encoded bytes before writing. `icons:check` checks every 64/128/256 production image and every 384 px reward chest delivery; `icons:study --check` checks proposals. `normalize.test.mjs` rejects an actual undersized delivery and a faint-border control. Model subject selection still requires visual review. |
| Normal validation and restoring delivered sources work without historical git objects.                                                 | Pinned committed archives and hashes; `source.test.mjs`; `icons:import`; `icons:study --check`. Revision fields document provenance only.                                                                                                                                                                                                                                                                                                        |
| A successful browser action must reach its intended state and satisfy the shared proof collector.                                      | `proveResourceIcons` checks the active tab and records `led`/`failed`; `proof-record.test.mjs` calls the actual proof and `problemsOf`, including decode, mapping and navigation failures.                                                                                                                                                                                                                                                       |

Do not repaint or alter a subject to fix padding. Rebuild through `normalizeMaster`. Historical comparisons remain exact
archived bytes; they are references, not production deliveries. Construction thumbnails retain their separate pipeline.

Reward rank-band chests use `rewardChestMeaning` and the approved sealed/opened images. `chest` is the world's crate.
`validate.test.mjs` rejects the old conflated mapping; `buildRewardChests` pins all ten archived originals, exports
through the normal normalizer, and checks fill and exact regenerated bytes for every registered delivery;
`reward-chests.test.mjs` rejects the actual undersized originals; `reward-panel.test.tsx` checks every band's title,
full artwork and Open button.

UI utilities use the owner-selected Ivory relief masters in the existing Facets catalog and renderer. The production
validator rejects a utility assigned another style, including a newly added meaning. Resource and world-object identity
stays separate: Transfer uses `transfer` (Ivory pack donkey); resource 25 uses `donkey` (resource painting). The catalog
pins each selected source master; the ordinary file check rejects stale exports and undersized deliveries.
