memory, and asset lifecycle) produced **184 findings**. Every critical/high finding (38) was then re-examined by an

(0 refuted); 15 had severity adjusted. Severities below are post-verification. Line numbers refer to the current `next`

## What is already good (build on it, don't regress it)

The codebase is unusually lifecycle-disciplined for its size. The dispose audit found **no critical unbounded GPU leak
during normal play**. Specifically worth preserving and extending:

- **Label render cadence gating** — `renderer-label-runtime.ts` `shouldRender()` + `game-renderer-policy.ts` skip CSS2D
  DOM renders unless dirty/active, view- and mobile-aware. Reuse this dirty/cadence pattern for any DOM- or GPU-coupled
  periodic work.
- **Single frame-pacing chokepoint** — `renderer-animation-runtime.ts` applies the selected render profile without
  changing visual output.
- **Centralized destroy path** — `renderer-destroy-runtime.ts` frees intervals/listeners/GUI/scenes/ backend in one
  ordered function; route/interaction runtimes pair add/remove listeners symmetrically.
- **Shared-resource infrastructure** — `utils/matrix-pool.ts`, `material-pool.ts`, `instanced-matrix-attribute-pool.ts`,
  `hex-geometry-pool.ts`, `labels/label-pool.ts`, refcounted point-label textures, module-level HDR environment cache
  with ownership-aware disposal (`renderer-backend.ts:200-220`).
- **Shared WebGPU renderer path** — native WebGPU and its upstream WebGL2 fallback use the same effects and scene
  runtime.

## The five problems that matter

1. **Cache-invalidation storms.** The terrain matrix cache, global pools, and hydration state are wiped wholesale by
   events that don't invalidate them logically (any structure count change, any army move, any explored-tile mutation
   via one global generation counter). The expensive caching machinery exists but is constantly self-defeating.
2. **Per-entity per-frame allocation churn.** Several hot paths allocate objects/closures _per moving army per frame_
   (BigInt noise biome resolution, label view models, attachment-sync closure bundles). GC pauses scale with army count
   — worst exactly when the screen is busy.
3. **Localized GPU leaks + one crash-class bug.** Pooled instanced attributes leak on dropped chunk transitions; arrival
   ghosts leak 2 ring geometries each; morph textures are never resized on capacity growth (out-of-bounds
   `Float32Array.set` → `RangeError` on the frame path once >64 animated army slots exist).
4. **Unbounded session-lifetime memory.** Explored tiles / entity hex maps (+ their game-worker mirrors), hydration
   fetch states, and the pools themselves grow monotonically across traversal — tens of MB after exploring a large map,
   with snapshot costs that scale with accumulated total.
5. **Double-resident assets.** The full biome GLB set is parsed and GPU-resident twice (Worldmap + Hexception both alive
   for the session); cosmetics preload retains a second copy of every army GLB; BuildingPreview re-parses the entire
   building catalog already loaded by HexceptionScene.
