# Why the client drifted from the chain, and how it stops — audit and Codex brief

Motto: **KISS, always. Systemic fixes over point patches. Success of systemic work is deletion.**

Owner question (2026-09-04): "how and why does this happen." "This" is the run of findings behind
`sign-out-and-tuple-wire-shape-codex-brief.md`: a generated schema that no longer matched Cairo, a stale source manifest
that would have reverted it, consumers still decoding a wire format retired six weeks ago, a parity test certifying the
retired behaviour, and a PR suite red for its whole visible history while every handoff reported green. Each was found
one at a time. They are one class.

Everything below is measured on `client-scale-96p` at `62be4308e8e`.

---

## 1. What happened, with numbers

**The generated schema was maintained by hand.**

- `packages/types/src/dojo/contract-components.ts` opens with "Autogenerated … Do not edit manually." It has 85 commits.
  The generator that owns it (`packages/types/scripts/generate-contract-components.ts`) was introduced on 2026-08-09
  (`4ffd7e45dcd`) and has 7 commits.
- Since the generator exists, the output has been edited by hand in 4 commits: `86a0f5311a4` (+1011 / −986),
  `b569e2aca6a` (+28 / −163), `bbdd1d03224` (+2 / −14), `89c06b471df` (+1 / −1). The two ledger commits added
  `LedgerRegistration`, `ledger_operator_address` and `player_registry_address` to the output without touching the
  manifest the generator reads.
- The generator was built to make that safe: `assembleGroup` splices any baseline block whose member **names** match, so
  a type change in Cairo never reaches the output. Run against HEAD it reports "33 spliced/unchanged, 79 generated, 6
  carried" and produces a 906-line diff that reverts the ledger fields, because its source manifest
  (`manifest_appchain_blitz.json`, built 2026-08-31) predates the Cairo it describes (2026-09-03).
- A pure generation from the fresh manifest with no splice differs from the committed file in 43 of 114 blocks, 20
  substantively: tuples labelled `"array"` (48 `ResourceArrival` slots), `u256` hand-written as `{ low, high }` (Herald
  ships one hex string), `ContractAddress` hand-written as `String` in five places, `u64` split 41 `Number` / 6 `BigInt`
  by feel, seven blocks for models Cairo deleted, two models Cairo added that the file lacks.

**Consumers were written against a wire format that no longer exists.**

- Torii was replaced by Herald on 2026-08-29 (`f5f226cd282`). Torii wrapped every scalar in `{ value }`; Herald sends
  plain JSON (`toJsonValue`, `apps/herald/src/model-registry.ts:190-205`).
- `packages/core/src/utils/resource-arrivals.ts:128-160` and `quest-entity-detail.tsx:64-70` still unwrap `{ value }`.
  Every arrival slot has decoded to resource 0 / amount 0 since 08-29. Nothing failed; the panel is just empty.
- Both tuple readers (`recs-game-sync-store.ts:132-144`, `hyperstructure-shareholders.ts:26-30`) keep a "legacy
  typed-value envelope" branch for a producer that is gone.

**The tests certified the past.**

- `recs-game-sync-store.parity.json` holds "50 real herald rows"; its `expected` values are, by its own header, "what
  the legacy `@dojoengine/state` path wrote into RECS for them." The test pins the retired path's output, not the wire.
- The shareholder fixture in `recs-game-sync-store.parity.test.ts:57` was invented (`[["0xa","0x1388"], {value: …}]`);
  the live shape is `{"0": …, "1": …}`. Green suite, red boot.
- 126 `*.source.test.ts` files in the client. 110 are pure text pins (`toContain` on lines of code), 5 are structural
  allow-lists, 10 mix both. 855 `toContain` assertions pin 95 source files. Twenty were added in the last six weeks;
  eight had rotted by 09-04 (a `return` became `await`; a fee top-up check was removed by design; a claim-rewards
  handler went with entry tokens; a dashboard file was deleted; a `public/` path was two levels off; one allow-list
  entry outlived its interval).

**Red was normal.**

- `test-client` on `feat/madara-lab`: no successful run in the last 40. Every run is `failure` or `cancelled`.
- Handoffs in this period report "73 focused tests passed", "58 tests passed", "verification passed": true statements
  about subsets, while the full suite had 12 red files. A green subset on a red suite is not evidence; it was accepted
  as evidence.
- `deploy-client.yml` is a manual dispatch with no dependency on any check. The build that failed to boot game 21
  shipped through it.
- `next` protection: one approving review, no required status checks, admins exempt. The 803-commit PR (#4907) shows
  `gallery` and `test-client` failing and is mergeable.

## 2. Why: the class

**Truth was pinned as text at every layer instead of derived from its source.** A hand-edited generated file, a manifest
copied at a point in time, consumers matching yesterday's JSON shape, tests asserting on lines of code, fixtures
asserting on a retired implementation's output. Each pin is correct the day it is written and has no mechanism to notice
when its source moves. The only thing that notices is a player, or a Codex run that happens to read the right file.

Three conditions let it compound:

1. **No boundary check in CI.** Cairo → manifest → generator → RECS schema → coercer → consumer has five hand-offs and
   zero assertions between them. The one test that looks at the boundary (parity) compares against the wrong side.
2. **A red suite carries no signal.** Once `test-client` is always red, a new red is invisible, subsets become the unit
   of proof, and "passed" stops meaning anything. Every agent in this period behaved rationally inside that.
3. **Repair by re-pinning.** The fix for a rotted `toContain` is a new `toContain`; the fix for a stale generated block
   is a hand edit; the fix for a wire change is a fallback branch. Each repair adds a pin. The splice exists to make
   re-pinning survive regeneration. The repo's own rule names this: a systemic fix that only adds code is suspect.

## 3. What stops it

Ordered by how much of the class each one closes. Items 1 and 2 are already specified in
`sign-out-and-tuple-wire-shape-codex-brief.md` §A.5 and are cited, not repeated.

1. **One author per derived artifact, and a no-op test.** The generator becomes a pure function of the committed Madara
   manifest; the splice, the baseline ref, `customTypes` and every hand block go; CI asserts regeneration is
   byte-identical. (§A.5.) Same rule, same test shape, for every other generated file in the repo:
   `grep -rl "Autogenerated\|Do not edit"` over `packages/` and `apps/` and give each one its no-op test or delete the
   header.
2. **Fixtures come from the producer, never from the consumer.** The parity fixture's `expected` is deleted; the test
   applies captured Herald rows and asserts the typed RECS value against the type table, not against what the old path
   wrote. Capture rows with one script (`scripts/capture-herald-fixture.ts`: game id, model list → JSON), commit the
   command line in the fixture header, and re-capture when the manifest changes. (§A.4, extended.)
3. **Manifest freshness is a test.** `sozo migrate` writes the manifest and needs a live world, so CI cannot rebuild it.
   It can check it: parse `#[dojo::model]` and `#[dojo::event]` struct names and member lists from
   `contracts/l3/game/src/**/*.cairo`, compare with `manifest_madara.json` tags and members, fail on any difference.
   That check would have flagged `manifest_appchain_blitz.json` on 2026-09-03 and the blitz/eternum profiles months ago.
   Runs in `test-contracts.yml`.
4. **Source-string tests: structural stays, textual goes.**
   - Keep the 15 structural gates (allow-lists over the file tree: polling discipline, console discipline, RECS query
     discipline, import policies, absorbed-surface deletions). They assert shape, not prose, and they caught real things
     this week (the leaderboard interval, the second `requestSignIn` caller). Move the ones that are expressible as lint
     to ESLint `no-restricted-imports` / `no-restricted-syntax` so they fail in the editor, not in CI.
   - Delete the 110 text-pin files. Where a pin protected a behaviour worth keeping, write the behaviour test; where it
     protected a refactor's shape, it protected nothing. Budget: one Codex pass, one commit per feature folder, the
     number of deleted assertions in each commit message. Expect ~800 assertions and ~100 files gone.
   - Rule going forward, one line in `apps/game/AGENTS.md`: a test may assert on the file tree, the import graph, an
     allow-list or a behaviour. It may not assert that a source file contains a string of code.
5. **CI is the gate, and the gate is required.** On `next`: `test-client`, `knip`, `prettier`, `test-contracts` become
   required status checks (repo settings, owner). `deploy-client.yml` gains a first job that fails unless the dispatched
   ref has a successful `test-client` run for the same SHA (`gh run list --commit`). Red on the branch means no deploy
   and no merge; that is the whole point.
6. **Handoff protocol.** A completion report cites the full-suite command and result for every touched package
   (`pnpm test` in `apps/game`, `pnpm exec vitest run` in the others), `pnpm run knip`, `pnpm run format`, and the
   typecheck. A subset run is context, never the verdict. Add it to the brief template and to `AGENTS.md`.
7. **Two agents, one worktree, one artifact.** The hand edits to the generated file came from different sessions in the
   same worktree. Items 1 and 5 make that impossible to land; nothing else is needed. Do not add a lock, a CODEOWNERS
   rule or a bot.

## 4. Gates

- Item 1: §A.5 gate. Item 2: `recs-game-sync-store.parity.json` has no `expected` key; the capture script is committed
  and its command line is in the fixture header.
- Item 3: a deliberate one-member rename in a Cairo model fails `test-contracts` locally before any manifest is rebuilt.
- Item 4: `find apps/game/src packages -name '*.source.test.ts' | wc -l` ≤ 20 and every survivor is an allow-list;
  `grep -rn 'toContain("' --include='*.source.test.ts'` over the same tree returns nothing that is a line of code.
- Item 5: a PR to `next` with a failing `test-client` shows "merging is blocked"; a `deploy-client` dispatch on a SHA
  with no green `test-client` run stops in its first job.
- Item 6: the next three Codex handoffs quote the full-suite lines verbatim.
